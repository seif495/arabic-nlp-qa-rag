# MS3 website on Vercel

The final MS3 chatbot, deployed as a Vercel project with **`web/` as the
Root Directory**. It replaces the Streamlit Cloud deployment of
`src/ms3/app/app.py`. That app still runs locally for development.

```
web/
├── api/index.py          # Vercel Python function (FastAPI): /api/config, /api/chat, /api/health
├── ms3web/               # lightweight RAG runtime (NumPy only, no TF / torch / LangChain)
│   ├── chat.py           # memory strategies, prompt strategies, generation modes, OOD handling
│   ├── retrieval.py      # BM25 over the MS3 transcript chunks
│   ├── model_b.py        # NumPy port of MS2 Model B (RoPE Transformer)
│   ├── tokenizer.py      # MS2 SentencePiece tokenizer + encoder input layout
│   ├── llm.py            # Groq → Gemini fallback over HTTPS
│   ├── prompts.py        # MS3 prompt strategies (synced with src/ms3/generation/prompts.py)
│   ├── normalize.py      # verbatim copy of src/ms2/metrics/normalize.py
│   └── assets/           # generated by `python -m src.cli.ms3 export-web`
├── public/               # static UI (index.html, app.js, styles.css)
├── requirements.txt      # fastapi, numpy, sentencepiece
├── vercel.json
└── dev_server.py         # local preview (uvicorn) of the same routing
```

## Deploy

1. On Vercel, go to **Add New → Project** and import `seif495/arabic-nlp-qa-rag`.
2. Set **Root Directory** to `web`. This matters: Vercel would otherwise install the
   repository root's `pyproject.toml` (torch via sentence-transformers,
   chromadb, streamlit, LangChain), which exceeds the function size limit.
3. Set **Framework Preset** to *Other*. Leave the build command empty.
4. Add these **Environment Variables**:
   | Name | Required | Notes |
   | --- | --- | --- |
   | `GROQ_API_KEY` | recommended | primary LLM (`llama-3.3-70b-versatile`) |
   | `GOOGLE_API_KEY` | optional | fallback LLM (Gemini) |
   | `GROQ_MODEL`, `GEMINI_MODEL` | optional | override the default model ids |
5. Click **Deploy**. Every push to `main` redeploys automatically.

You can deploy from the CLI instead:

```bash
cd web && npx vercel --prod
```

The site still works without any key: *MS2 only* mode answers with Model B alone.

## Where the MS2 RoPE model is used

Model B is the MS2 encoder-decoder Transformer with rotary positional
embeddings (`src/ms2/models/transformer/{rope,attention,model_b}.py`,
`docs/fs/ms2/ms2-rope-contract.md`). The site runs it in NumPy
(`ms3web/model_b.py`):

- **Re-ranking** (*Re-rank chunks with Model B*): the 30 BM25 candidates
  are re-ordered by a 50/50 blend of the normalised BM25 score and the cosine
  similarity between the masked-mean RoPE-encoder states of the question and
  of each chunk.
- **Generation** (*MS2 only* / *Hybrid*): Model B greedily decodes an answer
  over stride-`L_c/2` windows of the top 3 chunks, with a KV cache whose RoPE
  positions advance per step. It keeps the window with the best
  length-normalised log-probability.

RoPE rotates encoder self-attention Q/K and decoder masked self-attention Q/K
only. V and cross-attention are never rotated, as the MS2 contract requires.
`tests/web/test_model_b_parity.py` checks that the NumPy port matches the
TensorFlow model: RoPE tables, encoder states, teacher-forced logits, and
cached vs. full decoding.

### Shipped checkpoint

- Model: `ModelB()`, 2.28M parameters, seed 42.
- Training: trained on CPU with `train-model-b` (batch 16, Noam/Adam,
  label smoothing 0.1). It started overfitting after about 1k steps. The best
  dev loss was 5.30 at step 1000, and that checkpoint is the one exported.
- Weights: 4.2 MB `.npz` (float16). Greedy argmax agrees 100% with the
  float32 TensorFlow model on dev batches.
- Quality: weak, as expected for a from-scratch model trained on 3.5k pairs.
  On the first 40 dev examples, token-F1 is about 0.04 and EM is 0. The UI
  labels its answers as experimental, and *Hybrid* mode shows them next to
  the LLM's.
- Latency: about 30 ms per decode on CPU. A request with re-ranking plus
  generation takes about 1 s, excluding the LLM call.

## Rebuilding the assets

```bash
uv run python -m src.cli.ms1 run-all                         # MS1 normalised transcripts + dataset
uv pip install tensorflow-cpu                                # only needed to train/export Model B
uv run python -m src.cli.ms3 train-model-b                 # early-stops on dev loss
uv run python -m src.cli.ms3 export-web                      # writes web/ms3web/assets/
```

## Local preview

```bash
uv run python web/dev_server.py
```

Then open http://127.0.0.1:8000. Put `GROQ_API_KEY` in your shell
environment first.

## Differences from the Streamlit build

| | Streamlit (`src/ms3/app`) | Vercel (`web/`) |
| --- | --- | --- |
| Retrieval | ChromaDB + MiniLM embeddings | BM25 over the same 1000/200 chunks. torch does not fit in a function. |
| Retrieval query | LLM standalone query in the user's language | Always rewritten to Arabic, because the transcripts are Arabic and retrieval is lexical |
| MS2 models | Model A / Model B / sinusoidal "Transformer" via TensorFlow | Model B (RoPE) via NumPy |
| Conversation state | `st.session_state` | browser (`localStorage`), sent with each request |
| LLM calls | LangChain | plain HTTPS, same Groq → Gemini fallback |
