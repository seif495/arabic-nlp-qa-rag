# MS3 website on Vercel

The final MS3 chatbot, deployed as a Vercel project with **`web/` as the
Root Directory**. It replaces the Streamlit Cloud deployment of
`src/ms3/app/app.py`. That app still runs locally for development.

```
web/
├── api/index.py          # Vercel Python function (FastAPI): /api/config, /api/chat, /api/health
├── ms3web/               # lightweight RAG runtime (NumPy only, no TF / torch / LangChain)
│   ├── chat.py           # memory strategies, prompt strategies, generation modes, OOD handling
│   ├── retrieval.py      # BM25 over the MS3 transcript chunks
│   ├── ms2.py            # MS2 model runtimes + loader (default = selection winner)
│   ├── rnn.py            # NumPy port of MS2 Model A (tri-encoder RNN + FiLM)
│   ├── seq2seq.py        # NumPy port of the MS2 Transformers (Model B RoPE, vanilla sinusoidal)
│   ├── tokenizer.py      # MS2 SentencePiece tokenizer + encoder input layout
│   ├── llm.py            # Groq → Gemini fallback over HTTPS
│   ├── prompts.py        # MS3 prompt strategies (synced with src/ms3/generation/prompts.py)
│   ├── normalize.py      # verbatim copy of src/ms2/metrics/normalize.py
│   └── assets/           # generated by `python -m src.cli.ms3 export-web`
├── public/               # static UI (index.html, app.js, styles.css)
├── requirements.txt      # fastapi, numpy, sentencepiece
├── vercel.json
└── dev_server.py         # local preview (uvicorn) of the same routing
```

## Deploy

1. On Vercel, go to **Add New → Project** and import `seif495/arabic-nlp-qa-rag`.
2. Set **Root Directory** to `web`. This matters: Vercel would otherwise install the
   repository root's `pyproject.toml` (torch via sentence-transformers,
   chromadb, streamlit, LangChain), which exceeds the function size limit.
3. Set **Framework Preset** to *Other*. Leave the build command empty.
4. Add these **Environment Variables**:
   | Name | Required | Notes |
   | --- | --- | --- |
   | `GROQ_API_KEY` | recommended | primary LLM (`openai/gpt-oss-120b`; if Groq retires it, the server switches to an available model) |
   | `GOOGLE_API_KEY` | optional | fallback LLM (Gemini) |
   | `GROQ_MODEL`, `GEMINI_MODEL` | optional | override the default model ids |
5. Click **Deploy**. Every push to `main` redeploys automatically.

You can deploy from the CLI instead:

```bash
cd web && npx vercel --prod
```

The site still works without any key: *MS2 only* mode answers with the MS2 model alone.

## Which MS2 model the site uses

MS2 has four from-scratch generators. `select-ms2-web` trains them all with
one recipe (same MS1-derived caches, batch 16, seed 42, label smoothing 0.1,
clip 1.0, early stopping on dev loss) and ranks them by greedy-decoding
token-F1 on the full dev split (414 questions). The full table is in
[`docs/reports/ms3_web_model_selection.md`](../docs/reports/ms3_web_model_selection.md):

| Rank | Model | Params | Dev EM | Dev token-F1 | On the site |
| --- | --- | ---: | ---: | ---: | --- |
| 1 | Model A: tri-encoder RNN + FiLM decoder | 2.42M | **0.068** | **0.100** | **default** |
| 2 | Model B: RoPE Transformer | 2.28M | 0.058 | 0.097 | selectable |
| 3 | Vanilla Transformer (sinusoidal PE) | 4.10M | 0.046 | 0.087 | selectable |
| 4 | `rnn_model` (config-driven RNN variant) | 3.72M | 0.019 | 0.068 | not shipped |

Model A wins on all four metrics (EM, token-F1, char edit distance, BLEU-1),
but its lead over Model B is small. The vanilla Transformer has the lowest dev
*loss* yet ranks third on answers, which is why selection uses decoded
answers. The three shipped models are listed in the sidebar's
*MS2 model* picker, with Model A preselected.

The models are used in two places:

- **Re-ranking** (*Re-rank chunks with the MS2 model*): the 30 BM25
  candidates are re-ordered by a 50/50 blend of the normalised BM25 score and
  the cosine similarity between the model's question and chunk encodings.
  For Model A these are its Branch 1 pooled question and masked-mean Branch 2
  context states. For the Transformers they are masked-mean encoder states.
- **Generation** (*MS2 only* / *Hybrid*): the model greedily decodes an
  answer over stride-`L_c/2` windows of the top 3 chunks, batched for Model A.
  It keeps the window with the best length-normalised log-probability.

In Model B, RoPE rotates encoder self-attention Q/K and decoder masked
self-attention Q/K only. V and cross-attention are never rotated, as
`docs/fs/ms2/ms2-rope-contract.md` requires.

### Verification

- `tests/web/test_rnn_parity.py` and `tests/web/test_seq2seq_parity.py`
  check every NumPy port against TensorFlow: encoder states, teacher-forced
  logits, and cached/batched vs. full decoding. They are skipped without TF.
- `tests/web/test_model_a_inputs.py` checks that the web runtime builds Model
  A's question, context, joint and char tensors exactly like the MS2 pipeline.
- The exported float16 weights reproduce the TensorFlow dev scores exactly in
  NumPy (EM and token-F1 identical for all three models).
- Latency on CPU: re-ranking 30 chunks takes 0.2–0.8 s and generating over 6
  windows takes 0.2–0.5 s, depending on the model.
- Assets total about 17 MB: three `.npz` files, chunks, tokenizer and char
  vocab.

Quality is weak for every MS2 model, as expected for models trained from
scratch on 3.5k pairs. The UI labels their answers as experimental, and
*Hybrid* mode shows them next to the LLM's answer.

## Rebuilding the assets

```bash
uv run python -m src.cli.ms1 run-all                         # MS1 normalised transcripts + dataset
uv pip install tensorflow-cpu                                # only needed to train/export MS2 models
uv run python -m src.cli.ms3 train-ms2-web --model all       # all 4 MS2 models, early-stops on dev loss
uv run python -m src.cli.ms3 select-ms2-web                  # dev EM/F1, writes the selection report
uv run python -m src.cli.ms3 export-web                      # writes web/ms3web/assets/
```

## Local preview

```bash
uv run python web/dev_server.py
```

Then open http://127.0.0.1:8000. Put `GROQ_API_KEY` in your shell
environment first.

## Differences from the Streamlit build

| | Streamlit (`src/ms3/app`) | Vercel (`web/`) |
| --- | --- | --- |
| Retrieval | ChromaDB + MiniLM embeddings | BM25 over the same 1000/200 chunks. torch does not fit in a function. |
| Retrieval query | LLM standalone query in the user's language | Always rewritten to Arabic, because the transcripts are Arabic and retrieval is lexical |
| MS2 models | Model A / Model B / "Transformer" via TensorFlow (Model A and "Transformer" could not be imported before this change) | Model A (default), Model B (RoPE), vanilla Transformer via NumPy |
| Conversation state | `st.session_state` | browser (`localStorage`), sent with each request |
| LLM calls | LangChain | plain HTTPS, same Groq → Gemini fallback |
